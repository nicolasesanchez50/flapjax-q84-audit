6. How many distinct operators this implies

6 distinct recipients. Three have a resolvable first BNB funder, and all three funders are different: the treasury itself (which seeded 0xfb200657…24e6), the PancakeSwap V2 Router (a dust swap payout to 0x2ae18c3b…8a02), and contract 0xc1ea672c…570a via ERC-4337 (0xab39aa1e…0160). The remaining 4 have never held BNB and have never sent a transaction, so no funding link exists for them.

No two distinct recipients share a first funder on 1 November COT, and no recipient's first funder is another recipient of the day. So the funder data merges nobody: it implies 5 distinct operators behind the 6 addresses — one per funded address plus one per unlinkable address. That is the honest reading, not a claim that they are all genuinely different people: 4 addresses are simply unproven either way, because an address that has never touched BNB leaves no funding trail.

Cross-day context (from my own audits of the three previous days): 4 of the 6 recipients were also paid on at least one earlier day — the payout set is partly recurring, which is consistent with a stable roster of worker wallets rather than one-shot throwaways.

8. How to re-check every number

All data comes from public BSC state; no indexer and no proprietary API is used, so anyone can reproduce it with one public node. The exact log query for the outflow list:

{"jsonrpc":"2.0","id":1,"method":"eth_getLogs","params":[{
  "address":"0x90c8889f428F9Ebb77BB8f15CAD3a50a9aC680df",
  "fromBlock":"0x7cebcb4","toBlock":"0x7d01588",
  "topics":["0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef",
            "0x0000000000000000000000007c34e9e21ee28a49ff0b84b61774119e6633359f"]
}]}

= blocks 130989236–131077512, Transfer events with from = treasury. The inflow query is the same call with the treasury address in the third topic position. Block boundaries were found by binary search over eth_getBlockByNumber timestamps; the treasury balance check uses eth_call to balanceOf at blocks 130989235 and 131077512. Every tx hash, block and address above is also a BscScan link. The machine-readable dump of this audit (flapjax_q84_audit.json) is in the same public repository.

Do not trust a single range query on an arbitrary public node. Public BSC endpoints differ in log retention and result caps. Re-running the exact range query above on one widely used public endpoint (bsc-rpc.publicnode.com) returned only 5 of these 18 outflows for the whole range and only 2 in the 50,000-block chunk that holds 15 of them — a reader using it alone would silently under-count. Two checks that use no indexer and always work: (a) the treasury balance delta in section 2, which is exact to the wei, and (b) the 18 individual transaction receipts, each of which contains the Transfer log with from = treasury, the recipient as to, and the exact 18-decimal value. All 18 receipts were re-read that way and matched 18/18.
